# 기술 선택 기록

면접에서 "왜 이렇게 만들었어요?"에 답하기 위한 기록이에요. 항목마다 선택, 이유, 버린 대안을 적어요.

## 2026-10-12 Next.js (App Router) + TypeScript

- **선택**: Next.js App Router, TypeScript strict.
- **이유**: 채용 공고에서 가장 자주 요구되는 조합이고, 링크 미리보기와 SEO가 필요한 포트폴리오 특성상 빌드 시 HTML을 만드는 방식이 유리해요.
- **버린 대안**: Vite + React SPA(링크 미리보기와 SEO가 약함), Next.js + 외부 CMS(초기 설정이 과하고 외부 의존성이 생김).

## 2026-10-12 정적 생성(SSG)

- **선택**: 모든 페이지를 빌드 시점에 생성해요. 서버 로직이 필요 없어요.
- **이유**: 빠르고, Vercel 무료 플랜으로 충분하고, 운영할 서버가 없어요.
- **버린 대안**: 요청 시점 렌더링(SSR). 콘텐츠가 파일이라 요청마다 만들 이유가 없어요.

## 2026-10-12 CSS Modules + CSS 변수

- **선택**: 컴포넌트별 CSS Modules, 색/간격은 `styles/tokens.css`의 CSS 변수.
- **이유**: 퍼블리싱 경력의 핵심이 직접 짠 CSS라서, 그것이 그대로 보이는 방식이 전환 스토리에 맞아요. 클래스 이름 충돌은 모듈이 막아줘요.
- **버린 대안**: Tailwind(빠르지만 CSS 역량이 가려짐).

## 2026-10-12 설치된 실제 버전

- Next.js 16.4.0, React 19.3.0, TypeScript 5, Vitest 5.0.4, Node 24.14.0.
- `@types/node`를 `^20`에서 `^24`로 올렸어요. Vitest 5가 `^22 || >=24`를 요구해서 `npm install`이 충돌했고, `--force` 대신 실제 런타임(Node 24)에 맞게 타입 버전을 맞추는 쪽을 골랐어요.
- Next.js 16은 이전 버전과 API가 다를 수 있어서 `node_modules/next/dist/docs/`의 문서를 코드 작성 전에 확인해요(`AGENTS.md`의 안내).

## 2026-10-12 디자인 토큰: P2 청사진 + F2 (Noto Sans KR + JetBrains Mono)

- **선택**: 배경 `#12304f`, 격자선 `#1d416a`, 글자 `#f2f6fa`, 보조 글자 `#9db8d6`, 포인트 `#ffe14d`. 한글 본문과 제목은 Noto Sans KR(제목은 weight 500), 영문 라벨/코드는 JetBrains Mono(`.label` 클래스).
- **이유**: 첫 시안(도면 노트)의 방안지 격자를 가장 분명하게 살리는 색이고, 형광 노랑 포인트의 대비가 가장 커요. 모노스페이스는 한글을 못 그리는 경우가 많아서 한글은 Noto Sans KR, 영문 라벨과 코드는 JetBrains Mono로 역할을 나눴어요. 모노 글꼴로 쓰는 요소(로고, 라벨)에는 한글이 들어가지 않게 영문으로 써요. 한글이 들어가는 제목은 모노가 아니라 Noto Sans KR을 써요.
- **버린 대안**: 밝은 종이 방안지(P1), 크림 + 주황(P3). 다크 모드 토글은 범위 밖이라 만들지 않았고, 청사진은 토글이 아니라 사이트의 기본 색이에요.
- **명도 대비 (WCAG 공식으로 계산)**: 글자/배경 12.39, 글자/격자선 9.59, 보조 글자/배경 6.57, 보조 글자/격자선 5.09, 포인트/배경 10.33, 포인트 위 글자 10.33. 모두 4.5:1 이상이에요.
- **접근성 기본값**: `:focus-visible` 포커스 링(포인트 색), "본문으로 건너뛰기" 링크, `prefers-reduced-motion`에서 전환/애니메이션 끄기.

## 2026-10-12 Cache Components를 끄고 순수 정적 생성 사용

- **선택**: `next.config.ts`에서 `cacheComponents`와 `partialPrefetching`을 켜지 않아요. 상세 페이지는 `generateStaticParams`와 `dynamicParams = false`로 파일 개수만큼만 미리 만들고, 그 밖의 주소는 404예요.
- **이유**: create-next-app 16.4가 Cache Components를 기본으로 켜 뒀는데, 이 사이트는 빌드 때 파일을 읽어 굳히는 정적 페이지뿐이라 요청 시점 캐싱 모델이 필요 없어요. 켜 두면 `dynamicParams`를 쓸 수 없다는 점도 확인했어요(빌드 에러로 확인).
- **버린 대안**: Cache Components를 유지하고 `use cache`로 맞추는 방식(필요 없는 개념이 늘어남).
- **확인**: 프로덕션 서버에서 `/projects/this-portfolio` 200, `/projects/nope` 404, `/projects/..%2Fx` 404.

## 2026-10-12 슬러그는 정규식으로 검증

- **선택**: `getProject`가 슬러그를 `^[a-z0-9-]+$`로만 허용해요.
- **이유**: 슬러그가 파일명이라 `../` 같은 값이 들어오면 콘텐츠 폴더 밖 파일을 읽을 수 있어요. 처음에는 경로를 계산해서 비교했는데 Turbopack이 "프로젝트 전체를 추적한다"는 경고를 냈고, 정규식이 더 단순하고 경고도 없어서 바꿨어요.

## 2026-10-12 반응형과 접근성 점검 결과

- **가로 넘침**: 320px, 768px, 1280px에서 홈과 상세 페이지(`gulp-template`, `this-portfolio`)를 열고 화면 밖으로 나가는 요소를 스크립트로 찾았어요. 모두 0개이고 `scrollWidth`가 뷰포트 폭을 넘지 않아요. 카드는 320px에서 288px 폭이에요.
- **구조**: `<html lang="ko">`, 페이지당 `<main>` 1개와 `<h1>` 1개, 제목 레벨은 h1 → h2 → h3 순서, 이미지 `alt` 누락 없음, 탭 순서가 시각 순서와 같음(건너뛰기 링크 → 헤더 → 본문 → Contact).
- **필터**: 전체 4개 → 프론트엔드 1개 → 퍼블리싱 3개 → 전체 4개로 동작하고, 버튼에 `aria-pressed`가 있어요.
- **고친 문제 (점검 중 발견)**: ① 헤더 앵커(`#about` 등)가 상세 페이지에서는 같은 페이지만 찾아서 동작하지 않았어요 → `next/link`와 `/#about` 형태로 변경. ② 헤더 링크와 상세 페이지 링크의 터치 영역이 24~27px로 작았어요 → 패딩을 더해 40px 안팎으로 키움. 문장 속 링크는 WCAG 대상 크기 예외라 그대로 뒀어요.
- **하지 않은 것**: 실제 스크린 리더 테스트, 자동 접근성 도구(Lighthouse 등) 점수 측정. 측정하지 않은 수치는 주장하지 않아요.

## 2026-10-12 최종 검토에서 고친 것

- **콘텐츠 파일명 검증**: 영문 소문자, 숫자, 하이픈이 아닌 파일명(`병원.mdx`, `Yuni_Wine.mdx`)이 목록에는 나오는데 상세 페이지는 404가 되는 문제가 있었어요. 목록을 만드는 단계에서 파일명을 검사해 빌드가 실패하게 했어요.
- **링크 주소 검증**: `liveUrl`, `repoUrl`이 `http://` 또는 `https://`로 시작하지 않으면 빌드가 실패해요. 스킴이 없으면 상대 경로가 되어 404로 가기 때문이에요.
- **테스트 보강**: 파일명 검사가 항목 이름까지 확인하도록 `/"title"/`로 좁혔고, 정렬 동점 처리는 `compareProjects`로 분리해 직접 검증해요. 잘못된 `kind`, `stack`, `order`도 테스트해요.
- **Hero**: 이름과 "메일 보내기", "프로젝트 보기" 버튼을 추가했어요(설계 문서의 Hero 요구사항).
- **상세 페이지 미리보기**: 페이지마다 `openGraph` 제목과 설명을 따로 지정해요.
- **코드 블록**: `pre`가 페이지가 아니라 블록 안에서만 가로 스크롤돼요.
- **콘텐츠 서술 정정**: 프로젝트 소개 글에서 실제와 다르거나 확인할 수 없던 표현("테스트를 먼저 쓰고", "직접 골랐고", "TypeScript로 검증")을 사실에 맞게 고쳤어요.

## 2026-10-13 사이트가 썰렁하다는 피드백 반영

- **문제**: 글자만 있고 이미지가 없었고, 정보 종류(소개, 프로젝트, 연락처)가 적었어요.
- **시각 자료**: 공개된 작업물 3곳(Ezmedicom, Yuni Wine, Gulp 템플릿 데모)과 이 사이트를 1280×800으로 캡처해 JPEG(70~105KB)로 줄여 썼어요. 브라우저 창 캡처는 해상도가 낮아서(800×500) 헤드리스 브라우저로 정확한 크기에 찍었어요. 이미지에는 대체 텍스트를 필수로 했고(없으면 빌드 실패), 테스트를 먼저 작성했어요.
- **정보 섹션**: 경력(작성자가 알려준 사실만), 기술 스택(숙련도 막대나 퍼센트 없이 "업무에서 써 왔어요 / 익히는 중이에요"로만 구분), 일하는 방식 4단계를 추가했어요. 정확한 월을 모르는 시점은 적지 않았어요.
- **분위기**: Hero 오른쪽에 CSS 박스 모델 도면(장식이라 `aria-hidden`, 좁은 화면에서는 숨김), 섹션 사이 눈금자, 푸터(마지막 배포일은 빌드 시점에 계산)를 넣었어요. 색은 기존 3가지(네이비, 연한 파랑, 노랑)를 넘기지 않았어요.
- **버린 대안**: 기술 스택 숙련도 막대(근거 없는 수치), 그라데이션이나 글로우 같은 장식(처음 정한 "사람이 만든 느낌" 원칙과 충돌).

## 2026-10-13 404 페이지 한글화

- **문제**: Next 기본 404 화면이 영어 문구였고, `<main id="main">`이 없어서 "본문으로 건너뛰기" 링크가 갈 곳이 없었어요. 빌드 결과에는 `<title>`이 2개 들어 있기도 했어요.
- **선택**: `app/not-found.tsx`를 만들어 한글 안내, 처음으로/프로젝트로 가는 링크, 도면 노트 스타일(`status: 404;`)로 구성했어요. 루트 레이아웃 안에서 그려져서 헤더와 푸터는 그대로 보여요.
- **확인**: 존재하지 않는 주소 3종(`/projects/nope`, `/nothing-here`, `/projects/..%2Fx`)이 모두 404 상태 코드와 한글 제목을 내고, `<title>`은 1개, `noindex` 메타가 들어가요. 320/768/1280px에서 가로 넘침이 없고 건너뛰기 링크의 대상이 있어요.

## 2026-10-13 필터 결과를 스크린 리더에 알리기

- **문제**: 필터 버튼을 누르면 화면의 카드 목록은 바뀌는데, 스크린 리더 사용자는 버튼의 선택 상태(`aria-pressed`)만 듣고 목록이 바뀐 것은 알 수 없었어요.
- **선택**: 목록 위에 화면에는 보이지 않는 `role="status"` 영역을 두고 "프로젝트 N개"를 읽어 줘요. 결과가 0개면 화면의 빈 결과 문구와 같은 문장이에요. 문구는 `describeResult`로 한 곳에서 만들고 테스트를 먼저 작성했어요.
- **숨김 방식**: `display: none`이 아니라 1px로 잘라 숨기는 `.sr-only`예요. `display: none`은 스크린 리더도 읽지 않기 때문이에요.
- **확인**: 필터를 전체 → 프론트엔드 → 퍼블리싱 → 전체로 바꿨을 때 안내가 4개 → 1개 → 3개 → 4개로 바뀌고, 12개 페이지·폭 조합에서 가로 넘침이 없어요.
- **하지 않은 것**: 실제 스크린 리더(NVDA, VoiceOver)로 읽히는 소리는 확인하지 못했어요. 코드와 DOM 변화까지만 확인했어요.

## 2026-10-13 새 페이지 화면 점검 결과

- **방법**: 홈, `/qa-dashboard`, `/cms-preview`, 새 프로젝트 글을 헤드리스 브라우저로 열어 스크린샷(1280px, 320px)을 직접 보고, 글자색 대비(WCAG 공식), 탭 순서, 포커스 표시, 폭별 가로 넘침을 스크립트로 전부 계산했어요.
- **결과**: 글자색 대비 미달 0건, 탭 순서가 DOM 순서와 일치, 모든 포커스 가능한 요소에 포커스 표시가 있어요. `/cms-preview` 미리보기 iframe은 320px에서도 내용이 그려져요.
- **고친 문제**: Operations 섹션 아래 여백이 0이라 다음 섹션의 눈금자와 붙어 있었어요 → 다른 섹션과 같은 여백(`--space-6`)을 줬어요.
- **오탐으로 확인한 것**: 전체 페이지 캡처에서 빈 칸으로 보이던 Yuni Wine 카드 이미지와 CMS 미리보기 iframe은 실제로는 정상이에요(지연 로딩과 iframe이 캡처에 안 찍힌 것).
- **남은 것**: 새 프로젝트 카드 4개에는 썸네일이 없어서 카드 격자가 들쭉날쭉해요. "HTML 소스" 칸의 긴 줄은 오른쪽에서 잘려 보여요(가로 스크롤은 가능). 카드 높이가 행마다 달라요.
- **하지 않은 것**: 실제 스크린 리더로 읽히는 소리, 테두리(비텍스트) 대비. 후자는 이전에 보류한 항목 그대로예요(2.38:1).

## 2026-10-13 새 프로젝트 카드 썸네일 추가

- **문제**: 새 프로젝트 카드 4개에 이미지가 없어서 이미지가 있는 카드와 섞인 격자가 들쭉날쭉했어요.
- **선택**: 이 사이트 안의 데모 두 개(`/cms-preview`, `/qa-dashboard`)는 로컬 프로덕션 빌드에서, 나머지 두 개(콘텐츠 발행 체크리스트, 접근성 마크업 점검기)는 각 공개 주소에서 1280×800으로 캡처해 JPEG(37~103KB)로 줄였어요. 대체 텍스트는 실제로 찍힌 화면을 보고 썼어요.
- **확인**: 카드 8개 모두 이미지가 로드되고(320/1280px), 가로 넘침이 없어요.
- **알게 된 것**: 콘텐츠 발행 체크리스트 도구의 큰 제목이 1280px에서 "체크리스"/"트"로 한 글자만 줄바꿈돼요(해당 도구 자체의 레이아웃). 점검 스크립트의 콘솔 "오류 4건"은 Next가 넣은 CSS preload 경고였고 사용자 화면에는 영향이 없어요.

## 2026-10-14 CMS 컴포넌트 데모를 타입 25개로 확장

- **무엇을**: `/cms-preview`를 원본 CMS 도구의 타입 25개(01~07, 09~26)를 담은 데모로 바꿨어요. 입력을 정의한 데이터(필드 종류: 글, 본문, 이미지, 선택, 반복 목록, 표)를 읽어 폼을 그리는 편집기 하나가 모든 타입을 맡고, 타입마다 "입력 정의 + 기본값 + 화면 + 레이아웃 CSS"를 한 파일에 둬요(`lib/cms/types/typeNN.tsx`).
- **원본에서 가져온 것과 가져오지 않은 것**: 가져온 건 타입별 **입력 항목, 반복 구조, 선택 변형, 요소 중첩 구조**뿐이에요. 원본의 CSS, 문구, 이미지, Supabase, 메뉴 관리자, 이미지 업로드, 타입 27·28은 가져오지 않았어요. (처음에는 클래스 이름도 `demo-`로 새로 지었다가, 아래 "원본과 같은 마크업" 항목에서 원본과 같은 이름으로 바꿨어요.) 원본 소스는 저장소에 복사하지 않았고 읽기만 했어요.
- **안전**: `rich` 필드(제목, 본문)만 HTML을 받고 항상 허용 태그(`em`, `strong`, `b`, `i`, `br`)만 남겨요. 나머지 값은 React가 이스케이프해요. 이미지 주소는 이 사이트 경로나 `https://`만 허용하고, 표의 열 너비는 `auto`, 숫자, 숫자+`px/%/rem`만 허용해요. 미리보기는 `sandbox=""`인 iframe이에요. 공격 입력(`<script>`, `onerror`, `javascript:`, `expression()`)은 모든 타입의 본문 필드를 훑는 단위 테스트로 확인했고, 브라우저에서 직접 넣어 본 건 타입 01과 타입 26(표)이에요.
- **계획에서 고친 것**: ① 계획대로면 미리보기 iframe이 459px을 넘지 않아 PC 모습을 볼 수 없었어요. 미리보기를 두 열 아래 전체 폭으로 옮기고 "PC / 모바일(360px)" 전환을 넣었어요. ② React 19가 `<img>`가 있으면 렌더 결과 앞에 `<link rel="preload">`를 붙여서 복사하는 소스에 섞였어요. 테스트를 먼저 쓰고 앞쪽 `<link>`만 떼어 냈어요. ③ 선택 변형 중 03, 17, 18은 열 수가 아니라 방향, 제목 칸 폭, 글 스타일이라서 의미에 맞는 이름으로 썼어요.
- **줄인 것 (타입 26 표)**: 원본 편집기는 병합과 해제까지 함수가 14개나 되는 큰 UI예요. 이 데모는 **칸 편집, 행·열 추가/삭제(맨 끝), 열 너비**를 지원하고, **칸 병합을 만드는 화면은 없어요.** 병합이 있는 표를 그리는 경로와 값 보정(`hidden`을 병합 범위로 다시 계산)은 구현하고 테스트했어요. 머리글은 1행으로 고정이에요.
- **08번**: 원본 배포의 파일 목록에 `Type08`이 없어서 건너뛰었어요(의도된 결번인지는 확인하지 못했어요).
- **하지 않은 것**: 실제 스크린 리더로 읽히는 소리 확인, 접근성 점수 측정.

## 2026-10-14 CMS 데모가 만드는 HTML을 원본과 같게

- **무엇을**: `/cms-preview`가 만드는 HTML을 원본 CMS 도구의 출력과 같은 클래스 이름(`cms`, `cms-*`, `typeNN`, Bootstrap의 `row`/`col-*`/`d-*`/`img-fluid`/`w-100`), 같은 요소 중첩, 같은 인라인 SVG 도형(오각형, 육각형, 체크 원, 체크), 같은 조건부 출력으로 바꿨어요. 이 도구의 결과물을 CMS에 붙여 쓰는 흐름이 데모의 의미라서, 클래스가 다르면 데모가 실제 도구를 대신 보여 주지 못하기 때문이에요. `demo-` 이름과 이전 CSS는 모두 지웠어요.
- **공개 범위**: 공개 저장소에 원본과 같은 클래스 이름과 마크업, SVG 도형 경로를 두는 것은 사용자가 승인했어요. 원본 CSS는 가져오지 않았고, 위 클래스 이름에 맞는 CSS를 새로 썼어요(Bootstrap 클래스는 필요한 것만 직접 구현, lg 기준 992px). 원본 문구와 이미지, Supabase, 메뉴·슬라이드 관리자, 업로드, 타입 27·28은 여전히 제외예요.
- **원본과 일부러 다르게 둔 것(안전)**: 이미지 주소는 `safeImageSrc`로 걸러요. `rich` 필드는 허용 태그만 남겨요. 선택값은 목록에 있는 값만 받아요(없으면 원본 기본값). `alt`는 원본의 `"box"` 대신 빈 값이에요. 타입 26 표의 머리글 `scope` 속성은 원본에 없어서 넣지 않았어요. 타입 16의 비어 있는 아이콘 이미지는 `<img>` 없이 `cms-icon` 상자만 남겨요.
- **원본 그대로 둔 것**: 선택 변형 값(`col-auto`/`col-2`, `text-type-1`/`text-type-3`, `col-lg-3`/`col-lg-4` 등), 타입 18의 클래스 속 겹공백(`cms-img-list  text-type-1`), 모바일 이미지를 PC 이미지가 있을 때만 보여 주는 조건(타입 18, 20~23, 25), 큰 제목이 비면 넣지 않는 머리글(20, 21, 23), 타입 20·21의 빈 목록 칸 출력.
- **미리보기 폭**: PC 미리보기는 1100px 고정 폭을 영역에 맞춰 축소해서(최소 0.5배) 보여 주고, 모바일은 360px이에요. 원본 마크업이 Bootstrap lg(992px)를 기준으로 PC와 모바일 이미지를 바꾸기 때문이에요.
- **하지 않은 것**: 타입 09~15, 16~26 전부를 브라우저에서 눈으로 확인하지는 않았어요(테스트로 클래스·중첩·조건을 확인했고, 화면은 일부 타입만 봤어요).

## 2026-10-14 CMS 데모에 이미지 파일 첨부 추가

- **무엇을**: `/cms-preview`의 모든 이미지 입력에 "파일 첨부"를 더했어요(원본 도구도 파일을 고르는 방식). 기존 주소 입력도 그대로 쓸 수 있어요. 첨부한 파일은 브라우저에서 줄여서 data URL로 만들어 소스에 직접 넣고, **서버로 올리지 않아요.** "첨부 지우기" 버튼과 결과 안내(`role="status"`)가 있어요.
- **줄이는 방식**: PNG는 투명을 살리려고 PNG로, JPEG·WebP·GIF는 JPEG로 저장해요. 폭은 최대 1200px에서 시작하고, 결과가 약 450KB(data URL 600,000자)를 넘으면 900, 640, 420px로 다시 줄여요. 그래도 넘으면 "너무 커요"라고 안내해요. 원본 파일은 5MB까지, 애니메이션 GIF는 첫 장면만 남아요.
- **안전**: `safeImageSrc`가 `data:image/png|jpeg|webp|gif;base64,…` 형식만 추가로 받고, SVG와 그 밖의 `data:`는 계속 막아요(SVG는 스크립트를 담을 수 있어서). 길이 상한을 넘는 값은 `normalizeValues`가 중간에서 자르지 않고 비워요(잘린 그림이 되지 않게). 파일 형식과 크기는 첨부할 때도 한 번 더 확인해요.
- **알아 둘 점**: 소스 창에 매우 긴 한 줄(이미지 데이터)이 들어가요. 복사하면 전체가 복사돼요. 이전 항목의 "이미지 업로드는 제외"는 서버 업로드를 뜻하고, 이제 브라우저 안의 첨부만 지원해요.
- **하지 않은 것**: 첨부 이미지를 실제 CMS에 붙여 넣었을 때의 동작, 매우 큰 이미지 여러 장을 한꺼번에 넣었을 때의 속도 확인.
