# 포트폴리오의 AI스러운 인상 줄이기

이 저장소의 포트폴리오를 직접 수정해 주세요. 목표는 AI 사용 사실을 숨기는 것이 아니라, AI를 의식한 해명과 반복되는 템플릿 문구를 줄이고 김영빈의 실제 경력·판단·작업 방식이 먼저 보이게 만드는 것입니다.

## 작업 전 필수 확인

1. 루트 `AGENTS.md`를 읽고 따릅니다.
2. 코드를 수정하기 전에 이 프로젝트에 설치된 Next.js 버전의 관련 문서를 `node_modules/next/dist/docs/`에서 확인합니다.
3. 현재 구현과 콘텐츠를 먼저 읽고, 확인되지 않은 경력·성과·수치·사용자 반응은 절대 추가하지 않습니다.
4. 현재의 도면 노트 콘셉트(방안지 격자, 짙은 파랑, 노랑 포인트, 모노스페이스 라벨)는 유지합니다.
5. 기존 URL, 공개 데모 링크, 저장소 링크와 프로젝트의 사실관계는 유지합니다.

## 필수 수정

### 1. 첫 화면 문구를 강점 중심으로 수정

현재 문구:

> 웹 퍼블리셔에서 프론트엔드 개발자로 넘어가는 중이에요.

다음 문구로 바꿉니다.

> 반응형·접근성·CMS 운영 경험을 바탕으로 React와 Next.js로 화면을 만듭니다.

이 문구에 맞춰 이미지 대체 텍스트처럼 기존 제목을 인용하는 곳도 함께 수정합니다. `publisher.to(frontend)` 라벨과 이름, CTA는 유지합니다.

### 2. 홈의 `07 / ai` 섹션 제거

- `AiWorkflow`를 홈에서 제거합니다.
- 더 이상 사용되지 않는 `AiWorkflow.tsx`와 해당 CSS Module도 제거합니다.
- `contact` 섹션 번호를 `08`에서 `07`로 변경합니다.
- AI 사용 설명이 필요하면 프로젝트 상세의 실제 제작 맥락 안에 한두 문장만 남깁니다.
- “제가 직접 판단해요”, “AI는 보조 도구예요” 같은 방어적 문장을 홈의 독립 섹션으로 다시 만들지 않습니다.

### 3. `method`와 다른 문구의 템플릿 느낌 완화

- `method`는 유지하되 네 문장이 모두 똑같은 리듬으로 끝나지 않게 자연스럽게 다듬습니다.
- 사이트 전체에서 `~했어요`, `~예요`가 기계적으로 이어지는 부분을 고칩니다.
- 친근한 존댓말 톤은 유지합니다. 과장된 마케팅 문구나 추상적인 표현은 넣지 않습니다.
- 실제 행동, 선택, 검증 방법이 드러나는 문장을 우선합니다.

### 4. 반복되는 방어 문구 정리

아래 표현이 프로젝트마다 반복되지 않게 정리합니다.

- `별도 개인 프로젝트예요.`
- `실제 업무에 쓰였다는 뜻이 아니에요.`
- `효과나 수치는 적지 않아요.`
- `점수는 주장하지 않아요.`

원칙:

- frontmatter의 역할 표기처럼 구분에 필요한 `개인 프로젝트` 표시는 유지할 수 있습니다.
- 같은 상세 페이지 안에서 개인 프로젝트라는 설명을 두세 번 반복하지 않습니다.
- 정확성이나 한계를 이해하는 데 꼭 필요한 내용만 각 프로젝트의 `한계` 또는 `확인할 수 있는 것`에 한 번 남깁니다.
- 비공개 업무 정보, 개인정보 보호, 검증하지 않은 성과를 공개하지 않는다는 중요한 고지는 삭제하지 않습니다.
- 여러 프로젝트에 공통인 설명이 꼭 필요하면 프로젝트 목록 근처에 짧은 공통 안내 한 번으로 모읍니다.

### 5. 프로젝트 목록의 우선순위 정리

현재 프로젝트를 삭제하지 말고 다음 두 그룹으로 보여 주세요.

대표 프로젝트:

- 이 포트폴리오 사이트
- 8개 화면, 하나의 제작 환경
- 헬스케어 SCM 기업 사이트
- 와인 브랜드·상품 사이트
- CMS 컴포넌트 HTML 미리보기 도구
- Viewport Watch

작은 도구와 실험:

- 발행 점검 체크리스트 데모
- 콘텐츠 발행 체크리스트
- 접근성 마크업 점검기
- 웹페이지 접근성/표준 검수
- 퍼블리싱 가이드 챗봇

구현 원칙:

- 기존 `전체 / 퍼블리싱 / 프론트엔드` 필터는 정상 동작해야 합니다.
- 필터 적용 후에도 두 그룹의 제목과 개수가 정확해야 합니다.
- 빈 그룹은 표시하지 않습니다.
- `작은 도구와 실험`은 처음부터 모두 펼쳐 놓지 말고, 접근 가능한 기본 HTML 요소인 `details`/`summary` 등을 우선 검토합니다.
- 키보드 접근성과 현재 도면 콘셉트를 유지합니다.
- 분류를 위해 데이터가 필요하면 명시적인 frontmatter 필드를 추가하고 스키마와 테스트를 함께 수정합니다. 제목 문자열 비교로 분류하지 않습니다.

### 6. 퍼블리싱 가이드 챗봇 문구를 증거 중심으로 수정

`RAG`, `지어낸 답을 줄인다`는 표현을 앞세우지 말고 실제 동작과 검증 가능한 한계를 먼저 설명합니다.

- 어떤 공개 자료를 검색 근거로 사용하는지
- 답변이 근거 문서를 먼저 찾는 구조라는 점
- 근거가 부족할 때의 현재 한계
- 아직 정확도를 수치로 측정하지 않았다는 사실

위 내용을 간결하게 정리합니다. 실제 구현에서 확인되지 않는 출처 표시 기능이나 실패 처리 기능은 새로 있다고 쓰지 않습니다.

### 7. AI 사용 공개는 프로젝트 맥락 안에서만 간결하게 유지

`이 포트폴리오 사이트`, `Viewport Watch`처럼 AI 사용을 이미 밝힌 글에서는 사실을 숨기지 않습니다. 다만 도구를 변호하는 설명보다 무엇을 직접 선택하고 어떻게 검증했는지를 한 문장으로 정리합니다.

예시 방향:

> 초안 검토와 반복 작업에는 AI 코딩 도구를 활용했고, 구조 선택과 브라우저 검증은 직접 진행했습니다.

문맥에 맞게 고치되 모든 프로젝트에 이 문장을 복사하지 않습니다.

## 수정하지 말아야 할 것

- 경력 기간, 회사명, 프로젝트 참여 범위를 임의로 바꾸지 않습니다.
- 근거 없는 성과 수치, 접근성 점수, 속도 향상률을 추가하지 않습니다.
- 실제 업무 프로젝트와 개인 프로젝트의 경계를 흐리지 않습니다.
- 디자인을 흔한 흰색 카드형 SaaS 포트폴리오로 바꾸지 않습니다.
- 새 라이브러리나 의존성을 추가하지 않습니다.
- 요청 범위와 관계없는 CMS 데모, QA 도구 기능을 리팩터링하지 않습니다.

## 검증

수정 후 다음을 모두 확인해 주세요.

1. `npm test`
2. `npm run lint`
3. `npm run build`
4. 홈을 데스크톱과 모바일 폭에서 직접 확인
5. 프로젝트 필터별로 대표 프로젝트와 작은 도구 분류가 올바른지 확인
6. 키보드만으로 필터, 프로젝트 링크, `details`/`summary`, 연락처까지 이동 가능 확인
7. 가로 스크롤, 잘린 문장, 빈 그룹, 잘못된 섹션 번호가 없는지 확인

완료 보고에는 다음만 간결하게 적어 주세요.

- 바꾼 핵심 내용
- 수정한 파일
- 실행한 검증과 결과
- 남아 있는 판단 사항이나 확인하지 못한 부분
