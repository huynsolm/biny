# CMS 컴포넌트 25개 타입 데모 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/cms-preview`를 원본 CMS 도구의 타입 25개(01~07, 09~26)를 담은 데모로 바꾼다. 입력하면 HTML 소스가 만들어지고 샌드박스 미리보기가 바로 바뀐다.

**Architecture:** 타입마다 "입력 정의 + 기본값 + View(JSX) + 레이아웃 CSS"를 `lib/cms/types/typeNN.tsx`에 쓰고, 레지스트리가 모은다. 입력 폼은 정의를 읽어 그리는 편집기 하나가 맡는다. 소스는 `renderToStaticMarkup` + 자체 들여쓰기 정리로 만들고, 같은 문자열을 소스 창과 `sandbox=""` iframe에 쓴다.

**Tech Stack:** Next.js 16 (App Router, 정적 생성), React 19, TypeScript strict, CSS Modules, Vitest 5. 새 의존성은 추가하지 않는다.

**Spec:** `docs/superpowers/specs/2026-10-14-cms-25-types-design.md`

> `AGENTS.md`: 이 Next.js는 기존 지식과 다를 수 있다. 페이지 패턴은 `app/cms-preview/page.tsx`를 따른다.

## Global Constraints

- 원본의 CSS, 클래스 이름(`cms`, `cms-*`, `typeNN` 단독 클래스), 문구, 이미지 주소(`fxfile…`), Supabase·관리자·업로드·타입 27~28·Bootstrap을 가져오지 않는다. 클래스 이름은 `demo-` 접두사만 쓰고, 문구는 일반적인 안내형 한국어("제목을 입력해 보세요", "항목 1")만 쓴다.
- `rich` 필드(제목·본문)만 HTML을 받고, 항상 `sanitizeInline` 결과로만 `dangerouslySetInnerHTML`에 넣는다.
- 미리보기는 `<iframe sandbox="" srcDoc>`이고 `allow-*` 값이 없다.
- 입력 한도: 한 줄 글 120, `title` 쌍 글 60, `rich` 600, 이미지 주소 200, 반복 항목 12, 하위 목록 8, 표 10행×6열, 표 셀 100. 입력에는 `maxLength`, `renderHtml`도 같은 한도로 자른다.
- 이미지는 `/`로 시작하는 이 사이트 경로나 `https://`만 허용(`safeImageSrc`). 기본값은 `/images/cms-sample.svg`(PC), `/images/cms-sample-m.svg`(모바일).
- 항상 보이는 안내문: "샘플 데이터예요. 서버에 저장되지 않고, 개인이 만든 데모예요."
- 스타일은 `styles/tokens.css` 변수와 점선 카드 언어, 미리보기 CSS는 `demo-` 클래스만. 그라데이션·장식 그림자·새 애니메이션 금지. 터치 영역 44px, 320px 가로 넘침 없음, 보이는 레이블, `:focus-visible`, `prefers-reduced-motion` 유지.
- 각 작업 끝에 `npm test`, `npm run lint`, `npm run build`가 통과해야 한다. 구현은 `main`이 아닌 브랜치에서 하고, 병합과 푸시는 사용자 승인 뒤에만 한다. 작업마다 커밋한다.

## Review Focus

각 줄의 테스트나 확인은 해당 작업의 단계에 들어 있다.

1. `rich` 값에 `<img onerror=…>`, `<script>`, `<a href="javascript:…">`, 대문자 태그, 쪼개진 태그(`<<em>`), `<em onclick=…>`, 닫히지 않은 태그가 들어가도 허용 목록 밖은 글자로만 나온다. (Task 1)
2. 반복 항목이 최소/최대 경계일 때 추가·삭제가 무시되고, 중첩 목록(하위 목록)에서도 같은 규칙이 지켜진다. (Task 1, Task 2)
3. 한 번도 열지 않은 타입의 값이 기본값으로 시작하고, 타입을 오가도 각 타입의 입력이 유지된다. (Task 2)
4. 포맷터가 인라인 태그 안의 인라인 태그, 문단 안의 `<br>`, 빈 요소, 빈 값, 빈 문자열, 표 중첩, 긴 텍스트를 같은 규칙으로 정리한다. (Task 1, Task 7)
5. 소스 창의 문자열과 미리보기에 그려지는 문서가 같고(기본 이미지 인라인 치환만 다르다), 기본값 렌더 결과에 외부 주소가 없다. (Task 2, Task 8)

- Produces (`lib/cms/sanitize.ts`): `sanitizeInline(value: string): string` — 먼저 `escapeHtml`로 전부 이스케이프한 뒤, 이스케이프된 허용 태그 `<em>`, `</em>`, `<strong>`, `</strong>`, `<b>`, `</b>`, `<i>`, `</i>`, `<br>`, `<br/>`, `<br />`(대소문자 무시, 속성 없음, 태그 안 공백은 `<br />`의 한 칸만)를 원래 태그로 되돌린다. `<br>`류는 모두 `<br>`로 출력한다.
- Produces (`lib/cms/schema.ts`):
  - `type Path = (string | number)[]`
  - `type FieldValue = string | Values[]` 와 `type Values = { [key: string]: FieldValue }` (표 값은 Task 7에서 `FieldValue`에 추가한다)
  - `type Field = TextField | RichField | ImageField | SelectField | ListField` — 각각 `{ kind: "text" | "rich" | "image" | "select" | "list"; key: string; label: string }`에 `select`는 `options: { value: string; label: string }[]`, `list`는 `itemLabel: string; min: number; max: number; fields: Field[]`가 더해진다. `image`는 `device?: "pc" | "mobile"`(기본 `"pc"`)가 더해진다.
  - `const LIMITS = { text: 120, titlePart: 60, rich: 600, image: 200, listItems: 12, subItems: 8 }`
  - `normalizeValues(fields: Field[], values: Values): Values` — 정의에 없는 키는 버리고, 문자열은 종류별 한도로 자르며(`text` 필드의 `key`가 `small`/`big`이면 `titlePart`), `list`는 `max`로 자르고 `min`보다 적으면 빈 항목(`emptyItem`)으로 채운다. 중첩 목록에도 같은 규칙을 적용하고, 입력 객체를 바꾸지 않는다. 누락된 문자열은 `""`.
  - `emptyItem(list: ListField): Values`
  - `setAt(values: Values, path: Path, value: FieldValue): Values` — 예: `["contents", 0, "text"]`. 불변 갱신.
  - `addListItem(values: Values, path: Path, list: ListField): Values` — 최대 개수면 같은 객체를 반환.
  - `removeListItem(values: Values, path: Path, index: number, list: ListField): Values` — 최소 개수면 같은 객체를 반환.
- Produces (`lib/cms/format.ts`):
  - `formatHtml(markup: string): string` — `renderToStaticMarkup` 결과(태그 사이 공백 없음)를 정리한다. 규칙: 블록 요소는 한 줄씩, 중첩 깊이마다 2칸 들여쓰기. 인라인 요소(`em`, `strong`, `b`, `i`, `br`, `span`)와 텍스트는 부모에 블록 자식이 없으면 부모와 같은 줄에 둔다. 부모에 블록 자식과 텍스트가 섞여 있으면 텍스트도 한 줄을 차지한다. 빈 요소는 `<div></div>` 한 줄. 끝 개행 없음. 빈 문자열은 빈 문자열.
  - `renderHtml(type: CmsType, values: Values): string` — Task 2에서 `CmsType`이 생긴 뒤 구현한다(이 작업에서는 `formatHtml`만).
