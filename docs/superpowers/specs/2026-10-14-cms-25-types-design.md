# CMS 컴포넌트 25개 타입 데모 설계

작성일: 2026-10-14

## 1. 목적과 배경

- **목적**: 직접 만든 CMS 컴포넌트 도구의 타입 25개(01~07, 09~26)를 포트폴리오에서 눌러 볼 수 있는 데모로 다시 만든다. 텍스트를 입력하면 HTML 소스가 만들어지고 결과가 바로 보이는 흐름이다.
- **원본**: 작성자가 근무 시간 외에 직접 만든 개인 프로젝트(Vite + React, Vercel `work` 프로젝트). 원본의 타입 구조(입력 항목, 반복 항목, 선택 변형)를 옮기고, 클래스 이름은 `demo-`로 바꾸고, CSS는 새로 쓴다.
- **옮기지 않는 것**: Supabase, 메뉴(GNB) 관리자, 슬라이드 관리자, 이미지 업로드, 타입 27·28, Bootstrap 의존성, 원본의 CSS, 원본 이미지 서버 주소, 원본의 실제 병원 문구. 원본에 `08`이 없어서 25개이다.
- **데이터**: 샘플 데이터만. 서버, DB, 업로드, 저장(localStorage 포함)이 없다. 새로고침하면 기본값으로 돌아간다.
- **성공 기준**: `/cms-preview`에서 타입 25개를 고르고 입력하면 소스와 미리보기가 즉시 바뀌고, 허용되지 않은 HTML이나 스크립트가 실행되지 않으며, 소스·CSS·클래스 이름·이미지 주소에 원본 서버나 병원 이름이 하나도 없다.

## 2. 범위

**포함**: 타입 25개, 스키마로 그리는 입력 편집기, 실시간 HTML 소스, 소스 복사, 샌드박스 미리보기, 기본 이미지(PC·모바일 2종), 사례 페이지 문구 갱신.

**제외 (YAGNI)**: 타입 27·28, 업로드, 저장/불러오기, 소스 편집(소스 창은 읽기 전용), 다국어, 인쇄, 원본 CSS 이식.

## 3. 파일 구조

기존 `lib/cms/components.ts`, `tests/cms-components.test.ts`와 현재 3개 타입(제가 만든 것이라 원본에 없다)은 새 구조로 교체한다. `lib/cms/html.ts`(`escapeHtml`, `safeImageSrc`)는 유지한다.

```
lib/cms/schema.ts         입력 정의 형식, 값 정리(길이·개수 한도), 반복 항목 추가/삭제
lib/cms/sanitize.ts       sanitizeInline: 허용 인라인 태그만 남기고 나머지는 이스케이프
lib/cms/format.ts         renderHtml(type, values): renderToStaticMarkup + 들여쓰기 정리
lib/cms/registry.ts       25개 타입 목록(순서, id, 라벨)
lib/cms/types/typeNN.tsx  타입별: 입력 정의, 기본값, View(화면 컴포넌트)
lib/cms/preview.ts        미리보기 문서와 새 CSS(demo- 클래스), 기본 이미지 인라인
components/CmsPreview.tsx 타입 선택, 스키마 편집기, 소스 창, 복사, iframe (클라이언트)
components/CmsPreview.module.css
public/images/cms-sample.svg, cms-sample-m.svg   샘플 이미지(PC, 모바일)
tests/cms-*.test.ts
```

경계: `lib/cms/*`는 브라우저 API를 모른다(`react-dom/server`만 사용). 컴포넌트는 `renderHtml` 결과를 소스 창과 iframe에 그대로 쓴다.

## 4. 데이터 모델

**입력 정의(`Field`)** 는 다음 종류만 쓴다.

| kind | 설명 | 값 |
|---|---|---|
| `text` | 한 줄 글, 이스케이프 | `string` |
| `rich` | 제목·본문. 허용 인라인 HTML | `string` |
| `image` | 이미지 주소 하나(PC 또는 모바일) | `string` |
| `list` | 반복 항목 묶음(하위 필드, 최소/최대 개수) | `Item[]` |
| `select` | 변형 선택(예: 칸 수) | `string` |
| `table` | 표(타입 26) | 표 값 |

- 원본의 `title: [{ small, big }]`은 `list`(작은 글/큰 글 쌍)로, `contents`는 `list`로, 하위 목록(`subtext`)은 `list` 안의 `list`로 옮긴다.
- 타입 정의는 `{ id, label, fields, defaults, View }`. `View`는 `(values) => JSX`이고 `demo-` 클래스만 쓴다. 타입 03·09·17·18·25의 선택 변형은 `select` 필드이며 열 수 수정자(`demo-cols-N`)로 반영한다.
- **한도**: 한 줄 글 120자, `title` 쌍의 글 60자, `rich` 600자, 이미지 주소 200자, 반복 항목 12개, 하위 목록 8개, 표 10행×6열, 표 셀 100자. 입력에는 `maxLength`를 걸고, `renderHtml`도 같은 한도로 자른다. 항목 수가 범위를 벗어난 값은 범위로 맞춘다.
- **타입별 정의의 기준**: 각 타입의 입력 항목, 반복 구조, 변형, 요소 중첩 구조는 원본 `TypeNN.jsx`를 따른다. 원본의 클래스 이름, CSS, 이미지 주소, 문구는 따르지 않는다. 문구는 일반적인 안내형으로 쓴다("제목을 입력해 보세요" 등).
- **타입 26(표)**: 행·열 추가/삭제와 셀 편집을 포함한다. 셀 병합(`rowspan`/`colspan`) 편집이 이식에 비해 지나치게 크면 병합 없는 표로 줄이고, 줄였다는 사실을 계획 실행 기록과 최종 보고에 남긴다.

## 5. HTML 안전과 정리

- **sanitizeInline(value)**: 먼저 `&`, `<`, `>`, `"`, `'`을 모두 이스케이프한 뒤, 이스케이프된 허용 태그 `<em>`, `</em>`, `<strong>`, `</strong>`, `<b>`, `</b>`, `<i>`, `</i>`, `<br>`, `<br/>`, `<br />`(대소문자 무시, 속성 없음)만 원래 태그로 되돌린다. `<br>`는 항상 `<br>`로 출력한다. 속성이 붙은 태그나 허용 목록 밖 태그는 글자로 보인다. `&nbsp;` 같은 엔티티는 글자 그대로 보인다(원본과 다른 점).
- `rich` 값만 `dangerouslySetInnerHTML`에 `sanitizeInline` 결과로 넣는다. 다른 모든 값은 React가 이스케이프한다.
- **이미지**: `safeImageSrc`로 검사한다. 기본값은 `/images/cms-sample.svg`(PC)와 `/images/cms-sample-m.svg`(모바일). 이 사이트 경로와 `https://` 주소만 허용한다.
- **미리보기**: `<iframe sandbox="" srcDoc=…>`(`allow-*` 없음). 샌드박스 iframe은 이 사이트의 이미지 경로를 불러오지 못하므로, 미리보기 문서에서만 두 기본 이미지를 인라인(data URI)으로 바꾼다. 소스 창에는 원래 경로가 보인다.
- **소스 정리(format)**: `renderToStaticMarkup` 결과를 한 요소씩 줄 바꿈하고 중첩 깊이마다 2칸 들여쓴다. 텍스트와 인라인 태그(`em`, `strong`, `b`, `i`, `br`, `span`)는 부모 요소와 같은 줄에 둔다. 외부 의존성(`pretty`)은 추가하지 않는다.

## 6. 화면

- 위쪽: 제목, 항상 보이는 안내문 "샘플 데이터예요. 서버에 저장되지 않고, 개인이 만든 데모예요."
- 타입 선택(네이티브 `<select>`, 25개, 라벨은 "타입 NN · 짧은 설명"). 타입을 바꿔도 각 타입의 입력값은 메모리에 유지한다.
- 스키마 편집기: 필드 종류별 입력, 반복 항목의 "추가/삭제"(한계에서 비활성화), `select`, 표 편집(타입 26). 모든 입력에 보이는 레이블.
- 결과: HTML 소스(읽기 전용 `<textarea>`), "소스 복사"(성공/실패 안내는 `role="status"`, 실패 시 소스 선택), 미리보기 iframe. 입력이 바뀌면 복사 안내를 지운다. 항목을 지워 포커스가 사라지지 않게 포커스를 옮긴다.
- 스타일은 `styles/tokens.css` 변수와 점선 카드 언어를 쓴다. 넓은 화면은 편집기와 결과 두 열, 좁은 화면은 한 열.
- 미리보기 CSS는 새로 쓴다. 타입별 레이아웃(`demo-typeNN`)은 한 파일의 문자열에 모은다.

## 7. 접근성

- 입력·버튼·select의 높이 44px 이상, iframe `title="HTML 미리보기"`, 소스 창 레이블, 복사 결과 `role="status"`.
- 320px에서 가로 스크롤이 없다(소스 창은 창 안에서 가로 스크롤). 새 애니메이션은 없다. `prefers-reduced-motion` 유지.

## 8. 포트폴리오 연결

- `react-cms-preview.mdx`: "컴포넌트 타입은 3개뿐이에요"를 "직접 만든 도구의 타입 25개(01~07, 09~26)를 샘플 데이터로 다시 만든 데모"로 바꾸고, 원본의 Supabase·메뉴 관리자·업로드는 옮기지 않았다는 점을 한 줄로 밝힌다. 구현 항목의 "컴포넌트 타입을 골라 같은 화면에서 확인할 수 있게 했어요"는 유지한다.
- `app/cms-preview/page.tsx`의 "타입은 3개만 담은 작은 데모예요."를 "타입 25개를 담은 데모예요."로 바꾼다.
- 성과 수치, 원본 화면 링크, 원본 이미지는 쓰지 않는다.

## 9. 테스트와 확인

- **Vitest**: `sanitizeInline`(허용 태그 보존, 속성 있는 태그·`script`·이벤트 속성 이스케이프, `<br />` 정규화), 포맷터(중첩 들여쓰기, 인라인 유지, 빈 요소), 스키마 한도(길이, 개수, 범위 보정), 반복 항목 추가/삭제 규칙, 레지스트리(타입 25개, id 순서·중복 없음, 08 없음), 타입별 기본값 렌더(핵심 구조 요소와 `demo-` 클래스만 사용, `<script`·`fxfile`·외부 주소 없음), 샘플 이미지 외 이미지 주소 거부.
- **브라우저**: 타입 전환, 입력 즉시 반영, 반복 항목 추가/삭제, 선택 변형, 표 편집, `<script>`·허용 밖 태그 입력, 복사 성공/실패, 이미지 표시(PC·모바일 폭), 320px 가로 넘침, 키보드 조작, 44px 터치 영역.
- **빌드**: `npm test`, `npm run lint`, `npm run build`, `git diff --check`.
- 실제 스크린 리더 테스트와 접근성 점수 측정은 하지 않으며, 점수는 주장하지 않는다.
