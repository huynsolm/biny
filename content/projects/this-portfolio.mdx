## 만든 이유

퍼블리셔로 일한 결과물은 이미 있었지만, 프론트엔드로 넘어갈 수 있다는 걸 보여줄 결과물이 없었어요. 강의로 배운 React, Next.js, TypeScript를 실제로 쓰는 가장 빠른 방법이 제 포트폴리오를 직접 만드는 거라고 생각했어요.

## 선택과 이유

- **Next.js 정적 생성**: 링크를 보냈을 때 미리보기가 나오고 빨리 열려야 하는 사이트라서, 빌드 때 HTML을 만들어 두는 방식을 골랐어요. 서버를 운영할 필요도 없어요.
- **프로젝트 내용은 MDX 파일**: 프로젝트를 추가할 때 코드 대신 파일 하나만 추가하면 돼요. 이 글도 그런 파일이에요.
- **TypeScript로 콘텐츠 검증**: 파일의 필수 항목이 빠지면 빌드가 파일 이름과 항목 이름을 알려주며 실패해요. 이 로더는 테스트를 먼저 쓰고 구현했어요.
- **Tailwind 대신 CSS Modules와 CSS 변수**: 제 강점이 직접 짠 CSS라서, 그게 그대로 보이는 방식을 골랐어요. 색과 간격은 변수 한 곳에서 관리해요.
- **디자인은 도면 노트 콘셉트**: 방안지 격자, 모노스페이스 라벨, 형광 포인트 하나예요. 마크업 구조를 눈으로 읽는 퍼블리셔의 습관을 디자인으로 옮겼어요.

## 막혔던 부분

- **테스트 도구 설치 충돌**: Vitest를 설치하는데 `@types/node` 버전이 맞지 않아 설치가 막혔어요. 강제 설치 옵션 대신 실제 실행 환경인 Node 24에 맞게 타입 버전을 올려서 풀었어요.
- **모노스페이스와 한글**: 모노스페이스 글꼴은 한글을 못 그리는 경우가 많아서, 제목과 본문은 Noto Sans KR, 영문 라벨과 코드는 JetBrains Mono로 역할을 나눴어요.
- **명도 대비**: 색을 고른 뒤 글자와 배경, 격자선 위 글자까지 직접 대비를 계산했어요. 가장 낮은 조합이 5.09:1이에요.

## 만든 방식

AI 코딩 도구와 함께 만들었어요. 기술과 디자인 선택은 제가 직접 골랐고, 왜 그렇게 골랐는지는 저장소의 기록 문서(`docs/decisions.md`)에 남겼어요.
