## 문제

반응형 페이지는 데스크톱, 태블릿, 모바일마다 확인해야 해요. 배포 전후 화면을 눈으로만 살피면 확인한 근거가 남지 않고, 페이지가 늘수록 빠뜨릴 가능성도 커져요.

## 역할

기획, 구현, QA를 혼자 맡은 별도 개인 프로젝트예요.

## 구현

- 이름과 주소가 담긴 `sites.json`을 입력으로 받아 각 페이지를 검사해요.
- 승인한 기준 이미지(baseline)와 현재 캡처를 pixelmatch로 비교해요.
- Playwright로 실제 Chromium 렌더링을 캡처하고, 데스크톱 1440×900, 태블릿 768×1024, 모바일 390×844를 기본 크기로 써요.
- 캡처 전에 애니메이션과 전환을 끄고 폰트 로딩을 기다려요. 알려진 동적 요소는 `ignoreSelectors`로 가려서 실제 화면 변화에 집중해요.
- 한 주소가 실패해도 전체 작업이 멈추지 않고 결과를 하나씩 따로 기록해요.
- 변경 비율, 차이 이미지, HTTP 상태와 오류를 정적 HTML 리포트로 남겨요.

## 확인할 수 있는 것

로컬에서 실행하는 도구라서 공개 데모는 없어요. 실제 실행 결과 리포트 예시는 [사례 페이지](https://team-library.biny.cloud/portfolio/viewport-watch/)에서 볼 수 있어요.

기능을 추가할 때마다 테스트를 먼저 쓰고, 실제 로컬 예시 페이지에서 캡처부터 리포트까지의 전체 흐름을 확인했어요. AI는 구현 단계의 반복 작업과 문서화 보조로 썼고, 기준 승인과 결과 해석, 브라우저 검증은 직접 판단했어요.

별도 개인 프로젝트예요. 실제 업무에 쓰였다는 뜻이 아니라서 효과나 수치는 적지 않아요.
